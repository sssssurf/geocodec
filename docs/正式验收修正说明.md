# geocodec 正式验收缺陷修正（0.6.0）

历史修正记录：本页记录 2026-11-07 的修正；最新 2026-11-09 复核、实现范围和证据见 [完整复核](完整复核.md)。

日期：2026-11-07。最新收到的正式验收结论为未通过。
本页记录该反馈后的技术修正，不代表已获重审或正式通过，不倒填十月交付时间。

组委会指出 Plus Code `(40.6,129.7)`、长度 8 应为 `8QGFJP22+`，原实现输出
`8QGFJM2X+`；官方编码向量有 13 项不一致。复查确认属实：旧版虽在整数域生成
编码，进入整数域前的浮点乘法与 floor 仍把十进制边界向下量化了一单位。

## 实际修正

- 0.6.0 使用 Double 最短可往返十进制拼写，逐位整数乘法和进位精确取 floor。
  负数按负无穷方向取整，不引入全局 epsilon；边界下方的相邻浮点值保持在原格。
- 固定官方原始 CSV 的提交与哈希，复现并保留原 13 条错误，再将所有编码、
  解码、合法性、缩短/恢复向量纳入测试和 CI；不改期望、不排除失败案例。
- 增加边界两侧、8/10/15 位、符号及指数形式回归；公开示例和 CLI 也验证反馈案例。
- 原有未知不确定度/CRS 安全模型、误差传播与只读 API 检查继续运行。

```bash
moon run --target js cmd/main -- plus 40.6 129.7 8
node scripts/gen-olc-tests.mjs --check
moon run --target js examples/safety
```

首行现在输出 `plus: 8QGFJP22+`。全套测试为 **841 项**，其中官方向量 **766 条**：
302 编码、420 解码、25 合法性、19 缩短/恢复。
完整数值契约、边界适配、独立预期与容差见
[pluscode-conformance.md](pluscode-conformance.md)。
