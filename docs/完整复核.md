# geocodec 完整复核与改进（2026-11-09，0.7.0）

正式验收暴露了 Plus Code 前置量化错误。0.6.0 虽使全部官方直接数值向量通过，
测试仍没有完整经过用户实际使用的文本解析入口。本轮从文本、数值、几何、
转换、资源预算和发布消费者重新复核，而非只重复旧断言。

| 已复现问题 | 原因 | 当前处理 |
| --- | --- | --- |
| 文本 -2.804,7.003 / -25.798,-59.812 仍编码到相邻格 | 手工按 0.1 累加小数，与正常 Double 转换舍入不同 | 先校验有限文法，再使用 core/string 正确舍入；官方编码向量追加真实文本入口 |
| 日期线闭边界不包含同一经线 | 点把 180 规范为 -180，盒边界仍是 180 | 包含/相交/Location 包含使用一致的圆周经度语义 |
| 巨大覆盖预算绕过限制 | Int32 先乘后检查已溢出 | 在乘法前做除法预算检查 |
| 接近全球的跨日期线粗网格重复 | 两段列区间重叠，被枚举并计费两次 | 合并覆盖全部列的重叠区间，预算按唯一网格计算 |
| DMS 双符号、秒单位造成方向错误 | 方位和数值符号叠加，末尾小写 s 被识别为南向 | 拒绝符号/方位冲突；带 d/m 的小写 s 按秒；显式单位链要求顺序正确 |
| 极大已知 u 导致派生无穷或变成未知 | 2*u 和传播余量无有限表示 | 低层 URI 保留有限输入原文；统一 Location 拒绝无法有限表示的派生量，转换整体失败而不丢掉已知界 |

## 验证链改变

- 原始官方 **766 条**编码、解码、合法性和短码向量继续保留。
- 在 302 个编码测试块中，额外对 **278 条合法纬度**验证 decimal 文本入口，
  对 **256 条合法 URI 坐标**验证 geo URI 入口；它们不是新增的独立官方向量，
  不将附加断言虚报为新来源。原始文件与哈希没有修改。
- 新回归直接检查两条文本误码、溢出预算、16 个唯一格的预算、日期线、
  DMS、极小正 u 和极大有限输入的拒绝/保留边界。
- 公开安全示例同时检查文本入口和边界修复；独立消费者从 registry 安装，
  不使用本地依赖覆盖。原有 None/null、CRS 拒绝及只读模型验证继续运行。

```bash
node scripts/gen-olc-tests.mjs --check
moon test --target js
moon test --target wasm
moon test --target wasm-gc
moon test --target native
node scripts/check-semantics.mjs
```

记录保留在 docs/history。数值输入契约与官方数据适配详见 pluscode-conformance.md。
