# geocodec 初审补充说明

原意见指出“网格编码与坐标文本混为一类，缺少区域、精度、不确定度语义；转换是否丢失原始地点信息”。本次补充以统一模型、显式转换记录和可运行测试逐项回应。

| 初审关注点 | 当前实现与证据 |
| --- | --- |
| 网格与点不是同一类值 | LocationKind::Cell / Point；网格保留精确单元区域，坐标文本保留点语义 |
| 区域与精度 | region、resolution_m、area_m2；跨反子午线包围盒；尺寸与面积明确为近似值 |
| 不确定度 | uncertainty_m + uncertainty_known；缺失 u 不等于 u=0；极点包络与高精度 URI 覆盖测试 |
| 转换损失 | LocationConversion 同时保存 source/target，报告中心位移和传播后的源准确度界 |
| 是否损失原始地点 | 仅取中心会丢区域；换网格会量化且不保证覆盖原单元；转 geo URI 会丢形状。源模型与原文在转换记录内保留 |
| 可复现 | 62 项测试；CLI parse/convert/json；examples/basic；docs/reproducible-demo.md |

核心示例：40 m 不确定度的 geo URI 转为约 13.8 m 的 Plus Code 单元时，目标几何半径约 8.390 m，源不确定度仍为 40 m，围绕目标中心的传播界约为 47.428 m。编码变细不意味着测量更准。

已将申报中的“统一解析成 LatLng”更正为“统一解析成保留记法语义的 Location”。完整设计见 [location-model.md](location-model.md)，代码见 location.mbt、parse.mbt，回归测试见 location_test.mbt。

范围：只处理地点记法和转换语义；统一模型只支持 WGS84，不进行投影、坐标系转换或精密椭球测地计算。包围盒相交是保守范围判断，不等同于圆形区域的精确相交。
